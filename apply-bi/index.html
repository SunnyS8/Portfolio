Откликаюсь на позицию Project / Product Manager в направлении BI и отчётности.

Отчётность для меня не чужая тема, а ежедневная. Три года строю управленческую отчётность в Power BI и Excel: продажи, остатки, дебиторка, ассортимент, промо, оборачиваемость. Последние два года — маркетплейс-контекст: остатки по складам, динамика прихода и расхода, позиции, которые перестали двигаться. Знаю, как такие отчёты выглядят не на бумаге, а в жизни заказчика.

Умею превращать хаос запросов в приоритеты. Задач всегда больше, чем ресурсов. Разбираю входящие, отбираю по бизнес-эффекту, остальное объясняю заказчику с причинами. Бэклог без объяснения приоритетов превращается в список обещаний, которым никто не доверяет, — и говорить «нет» в такой ситуации не страшно, потому что есть аргумент.

Запрос почти никогда не формулируется так, как нужно. Приходит «нужен отчёт по продажам» — а дальше выясняется, что нужен фильтр по статусу, потому что в текущем виде туда попадают позиции, которых в системе просто нет. Разбираюсь до постановки задачи, а не после.

Есть опыт поставки BI-решений под ключ. Собрала приложение с 13 типами отчётов для отдела продаж: сама выявила потребность, написала ТЗ, приняла работу подрядчика, перевела пользователей, обучила — дальше веду сама: обновления, новые запросы, правила расчёта и документация. Отдельно — дашборд неликвидов прямо из выгрузок 1С в браузере.

Инструменты. Power BI, Excel (сводные, сложные формулы, Power Query), SQL, Python и pandas для обработки выгрузок 500k+ строк. Данные из 1С. Автоматизирую рутинные отчёты на Python — то, что занимало несколько дней ручной работы, собирается само по расписанию.

AI как усиление. Собрала агента для управления контекстной рекламой на LLM: FastAPI, Next.js, Telegram-бот, детерминированные правила решений, DRY_RUN, аудит-лог. Понимаю, где AI ускоряет, а где добавляет работы.

Про BPMN честно. Формально в нотации не работала. Процессы выстраиваю через описание, бизнес-правила и критерии приёмки — на это и опираюсь в приёмке. Освоить BPMN планирую, это вопрос недели, а не месяцев.

Как проходит путь от запроса до приёмки

01 / запрос

Разбор

Бизнес приходит с формулировкой задачи, а не с техническим заданием. Разбираю, что на самом деле нужно, ищу первопричину: нет данных, не тот статус, не та группировка.

02 / правила

Формализация

Фиксирую метрики, бизнес-правила и критерии приёмки. Пока правило расчёта не записано словами, его всегда можно посчитать двумя способами.

03 / приоритет

Согласование

Собираю бэклог целиком, отбираю по бизнес-эффекту. Не попало в этот релиз — объясняю заказчику почему, с аргументом и сроками.

04 / поставка

ТЗ и сроки

Декомпозирую на понятные части, фиксирую критерии приёмки. Разработка получает задачу, которую можно проверить, а не описать в общих словах.

05 / приёмка

Проверка на данных

Сверяю результат с источником, а не с ожиданиями. Проверяю на данных, где отчёт должен вести себя иначе: пустые значения, аномалии, пропущенные периоды.

06 / передача

Документация и обучение

Правила расчёта, описание показателей, инструкция — в том числе, чтобы следующий человек мог проверить любую цифру сам.

Главный принцип приоритизации. Бэклог без объяснения приоритетов превращается в список обещаний, которым никто не доверяет. Поэтому каждое «нет» или «не в этот релиз» сопровождается причиной: что даёт задача, сколько стоит, что будет, если её отложить. Это и есть работа по общению с бизнесом, а не формальная расстановка приоритетов в трекере.

Задача

Отчётность отдела продаж собиралась из выгрузок 1С вручную: продажи, остатки, задолженность по менеджерам, неоплаченные счета, незакрытые ЭДО — каждый отчёт отдельным файлом и своей логикой.

Что сделала лично я

Выявила потребность, написала ТЗ, приняла работу подрядчика, перевела пользователей и обучила. Дальше веду сама: обновления, новые запросы, документация. Неликвиды считаются по формуле «цена × длина × ширина × рулоны» — под рулонные материалы. Пени по неоплаченным счетам, план против факта с отклонением. Глобальный фильтр по датам: выбрал период — пересчитались все отчёты.

Инсайт

«Отчёт по продажам» — это не одна таблица, а десяток разных вопросов: директор спрашивает одно, кладовщик другое, бухгалтер третье. Когда каждая выгрузка открывается отдельно, одну и ту же работу повторяют каждую неделю.

FastAPI · pandas · openpyxl · Jinja2 · Bootstrap · выгрузки 1С

Дашборд неликвидов

[BI · Данные 1С]

Задача

Список неликвидов от РОПа, остатки и продажи из 1С — три отдельных Excel-файла, которые сводились копированием между таблицами.

Что сделала лично я

Решение на чистом фронтенде: Excel разбирается прямо в браузере, без сервера и без выгрузки на чужой аккаунт. Сопоставление по ключу «код + ширина» — один артикул существует в нескольких вариантах ширины, и наивное соединение даёт задвоение. Четыре статуса позиции, графики по складам, экспорт обратно в Excel.

Что пришлось исправить

Статус вычисляется автоматически и используется как фильтр. Сначала смотрят «остаток есть, продаж нет» — это работа для закупщика; всё остальное — контроль качества данных. Заодно нашла и починила ошибку в расчёте продаж и невидимые графики: canvas без заданной высоты при включённом responsive-режиме.

Автоматизация выгрузок

[ETL · Python]

Задача

Регулярная отчётность собиралась вручную: выгрузка, обработка в Excel, раскладка по файлам. На ежемесячные цикры уходили дни.

Что сделала лично я

Перенесла обработку в Python: pandas и openpyxl разбирают выгрузку 1С, считают показатели, формируют отчёты и раскладывают их по назначению. Запуск по расписанию. Плюс ABC/XYZ-анализ ассортимента поверх тех же данных.

Инсайт

Автоматизация без проверяемых правил расчёта просто переносит ошибку из Excel в код — и делает это быстрее. Поэтому правила фиксируются текстом до автоматизации, а не после.

Python · pandas · openpyxl · SQL · выгрузки 500k+ строк

Как считаю результат. Отчёт оценивается не по факту сдачи, а по решениям, которые бизнес принимает с его помощью. Поэтому в каждом отчёте есть явный сигнал: где показатель выходит за границы, где данных не хватает, где источник расходится. Панель, после которой не нужно ничего уточнять в Excel, — это отчёт, который работает.
